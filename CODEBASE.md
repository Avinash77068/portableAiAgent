# PORTABLE.AI — Codebase Map

A private, local-first AI desktop app (Electron + React). Every response is generated by a local `llama.cpp` server running on the user's own machine — no cloud AI, no account. Designed to run from a portable folder (e.g. a USB drive): the packaged app, its runtime binary, GGUF models, and its SQLite database all live as sibling folders next to the executable.

## How the three processes fit together

- **`src/`** — the renderer (React UI), running in a sandboxed Chromium window. Has no direct Node/filesystem access.
- **`electron/preload.cjs`** — the only bridge between renderer and main process. Exposes a `window.portableAI` object via `contextBridge`; every renderer→main call goes through an IPC channel defined here.
- **`electron/*.cjs` (main process)** — actual Node.js code: SQLite database, spawning/talking to `llama-server`, filesystem access, hardware detection.

Renderer code can **never** touch the filesystem or spawn processes directly — it always goes `src/ → preload.cjs → ipc/*Handlers.cjs → the actual logic`.

## `electron/` — main process

### Entry points
| File | Purpose |
|---|---|
| `main.cjs` | **The real entry point** (referenced by `package.json`'s `"main"`). Creates the `BrowserWindow`, registers every IPC handler module in order, auto-starts the AI server if a model is already selected, and handles graceful shutdown (`before-quit` stops the llama-server and closes the DB before the app exits). |
| `preload.cjs` | **The real preload script.** Defines the entire `window.portableAI` API surface: `conversations`, `messages`, `hardware`, `attachments`, `ai`, `agent`. |
| `main.js`, `preload.js` | ⚠️ **Dead code.** Early scaffold versions from before the database/AI/agent features existed. Nothing references them (`package.json` points at the `.cjs` files). Safe to delete. |
| `settings.cjs` | Tiny shared JSON key-value store at `data/settings.json` (used for the selected model id, agent's granted repo folder, auto-apply flag). |
| `attachments.cjs` | Validates and saves a chat attachment (image/PDF/text/code file) to `data/attachments/`, and extracts text from it (PDF via `pdf-parse`) when the AI needs it. |

### `electron/database/` — SQLite persistence (`better-sqlite3`)
| File | Purpose |
|---|---|
| `database.cjs` | Opens/creates `data/chats.db`, creates the `conversations`/`messages` tables. **`resolvePortableRoot()` lives here** — the function that makes the whole app portable: in dev it's the project folder; when packaged, it's the folder containing the `.exe` (Windows) or the folder containing the `.app` bundle (macOS — walks up 3 levels past `Contents/MacOS/`, since a signed `.app`'s real binary sits nested inside it). |
| `conversations.cjs` | CRUD for conversations (list/get/create/rename/delete). |
| `messages.cjs` | CRUD for messages within a conversation; deleting/creating a message also bumps the parent conversation's `updated_at`. |

### `electron/ai/` — talking to the local model
| File | Purpose |
|---|---|
| `LocalAIManager.cjs` | The orchestrator chat uses. Builds the actual prompt sent to the model: injects the current date/time (via `Intl`, not hardcoded — see "time queries" below), appends attachment text, runs web search when enabled, trims history to fit the context window, then calls `LlamaServerManager.generate()`. |
| `LlamaServerManager.cjs` | Owns the `llama-server` child process: finds the binary (`runtime/<platform>/llama-server[.exe]`), builds its CLI args (`--ctx-size`, `--threads`, `--n-gpu-layers`, all from `computeAIConfig`), starts/stops it, and streams `/v1/chat/completions` responses back token-by-token. |
| `webSearch.cjs` | Scrapes DuckDuckGo's keyless HTML endpoint (`html.duckduckgo.com/html/`) for up to 5 results. Also extracts a UTC/GMT offset mentioned in a snippet (e.g. "UTC+9") so a *different* place's current time can be computed exactly, instead of asking the model to do timezone arithmetic (it reliably gets that wrong). |
| `portManager.cjs` | Finds a free localhost port for `llama-server` to bind to. |
| `logger.cjs` | Appends timestamped lines to `logs/app.log`; swallows its own errors so logging can never crash the app. |
| `types.cjs` | The `AI_STATES` enum (`STOPPED`/`STARTING`/`READY`/`GENERATING`/`STOPPING`/`ERROR`). |

### `electron/hardware/` — sizing the model to the machine
| File | Purpose |
|---|---|
| `HardwareManager.cjs` | Detects RAM/CPU (`os.totalmem()`, `os.cpus()`), caches that snapshot for the app's lifetime. `computeAIConfig(selectedModel)` is the one exported function everything else calls — it's *not* cached, since the right config depends on which model is currently selected. |
| `performanceProfile.cjs` | Two tiers: a static fallback table (LOW_RAM/BALANCED/HIGH_PERFORMANCE → context length, threads, GPU layers), and `getModelAwareAIConfig()` — the real logic. It reads the selected model's *actual* architecture (via `ggufMetadata.cjs`), computes real KV-cache bytes-per-token, and sizes the context window to whatever fits in this machine's RAM (capped at the model's own trained max context). |

### `electron/model/`
| File | Purpose |
|---|---|
| `ModelManager.cjs` | Scans `models/*.gguf`, remembers which one is selected (`data/settings.json`), turns filenames into display names. |
| `ggufMetadata.cjs` | A minimal GGUF binary-header parser (no dependency) — reads just enough of a `.gguf` file to learn its layer count, embedding size, attention head counts, and native context length, without touching the (multi-GB) tensor data. This is what makes `computeAIConfig` model-aware. |

### `electron/agent/` — the "Repo Assistant" (grants a folder, fixes things in it)
| File | Purpose |
|---|---|
| `repoAccess.cjs` | Stores/reads the one folder the user has granted access to. `resolveInRepo()` is the sandbox boundary — refuses any path that would escape the granted folder (lexically via `../..`, or physically via a symlink), while treating model-style absolute paths (`/src/App.tsx`) as relative to the repo root rather than the real filesystem root. |
| `fileTools.cjs` | The actual sandboxed operations: `listTree`, `readFile` (capped, text-files only), `searchFiles` (plain substring search), `writeFile`. Every path goes through `resolveInRepo` first. |
| `tools.cjs` | The OpenAI-style tool schemas (`list_files`/`read_file`/`search_files`/`write_file`) handed to the model, plus a dispatcher for the three read-only ones. |
| `diff.cjs` | A small dependency-free LCS line-diff, used to show a reviewable before/after when the agent proposes a file change. |
| `AgentSession.cjs` | The actual agentic loop: sends the conversation + tool schemas to `llama-server`, executes whatever tool the model calls, feeds the result back, repeats (capped at 14 steps). Notable pieces: `trimToFit()` (drops the oldest tool exchanges once the conversation would exceed the model's context window), the "stall nudge" (if the model narrates an action instead of taking it, it gets told to actually call the tool, up to 4 times, instead of silently ending the run), and `requestCompletionWithRetry()` (retries a failed request — e.g. a truncated tool-call argument — a few times before giving up). `write_file` always goes through a diff; it's only actually written immediately if auto-apply is on, otherwise it waits for `resolveDiff(true/false)`. |

### `electron/ipc/` — the IPC surface (renderer ↔ main)
| File | Registers |
|---|---|
| `chatHandlers.cjs` | `portableai:conversations:*`, `portableai:messages:*` |
| `aiHandlers.cjs` | `portableai:ai:*` (status/models/select/start/stop/generate/stop-generation) — owns the one `LocalAIManager` instance and broadcasts status changes to every window. |
| `attachmentHandlers.cjs` | `portableai:attachments:save` |
| `hardwareHandlers.cjs` | `portableai:hardware:get-info` — merges the cached hardware snapshot with the *currently selected model's* AI config. |
| `agentHandlers.cjs` | `portableai:agent:*` — folder picker (native `dialog.showOpenDialog`), running a session, approve/reject a pending diff, auto-apply toggle. Shares the same `LlamaServerManager` instance as chat (via the `aiManager` passed in from `main.cjs`) rather than spinning up a second local server. |

## `src/` — renderer (React)

| File | Purpose |
|---|---|
| `main.tsx` | React root — renders `<App />`. |
| `App.tsx` | The whole app shell: sidebar + chat + composer + header (model picker dropdown, theme toggle, Repo Assistant launcher) + Settings modal + rename/edit dialogs + toast. Owns most top-level state (`conversations`, `messages`, `draft`, `webSearchEnabled`, etc.) and every handler that calls into `window.portableAI`. |
| `portableAI.d.ts` | TypeScript types for the entire `window.portableAI` bridge — must be kept in sync with `preload.cjs` by hand (nothing generates it automatically). |
| `index.css` | Tailwind entry + the light/dark theme CSS variables (`--app-bg`, `--text-primary`, etc.) + a couple of global resets (e.g. `cursor: pointer` on every enabled button). |

### `src/components/`
| File | Purpose |
|---|---|
| `Sidebar.tsx` | Conversation list (grouped Today/Yesterday/Previous 7 Days/Older), search, new-chat, settings entry. |
| `MessageBubble.tsx` | Renders one chat message — ChatGPT-style (borderless flowing text for the assistant, a plain grey bubble for the user) with hover actions (copy/edit/delete/regenerate). Also exports `StreamingBubble` for the in-progress response. |
| `MarkdownRenderer.tsx` | A small hand-rolled Markdown renderer (headings, lists, bold/italic, links, inline code, fenced code blocks with a copy button) — no external Markdown library. |
| `AttachmentPreview.tsx` / `AttachmentChip.tsx` | The row of attachment chips above the composer; a chip shows an actual image thumbnail for images (via a local `URL.createObjectURL`), an icon otherwise. |
| `AgentPanel.tsx` | The Repo Assistant's UI: folder picker, auto-apply toggle, the growing transcript (tool calls, results, diffs, final answer), the problem input. |
| `DiffView.tsx` | Renders one `diff.cjs` result as colored add/remove/context lines, with Apply/Reject buttons when a diff is still pending. |
| `SplashScreen.tsx` | The brief loading screen shown on startup. |

### `src/hooks/`
| File | Purpose |
|---|---|
| `useAttachments.ts` | Owns pending-attachment state: validates file extensions, creates a local preview URL for images, calls `window.portableAI.attachments.save`, cleans up object URLs on remove/reset. |
| `useAgentSession.ts` | Owns all Repo Assistant state: folder info, auto-apply, the accumulating transcript (`steps` — never wiped between runs, only via explicit `clearHistory`), the pending diff, and subscribes to `agent.onEvent`. Also catches a `run()` rejection (e.g. no model ready) and turns it into a visible error step, so a failed run is never silent. |
| `useTheme.ts` | Applies `data-theme` to `<html>` based on the chosen mode (dark/light/system), and follows the OS theme live when set to "system". |
| `useKeyboardShortcuts.ts` | ⌘/Ctrl+N (new chat), ⌘/Ctrl+K (focus search), Escape (close settings / blur search). |
| `useSplashScreen.ts` | Keeps the splash screen up for a minimum duration even if loading finishes instantly, to avoid a jarring flash. |

### `src/utils/`
| File | Purpose |
|---|---|
| `conversations.ts` | Groups conversations by recency for the sidebar, and derives a short conversation title from the first message. |
| `formatters.ts` | Formats bytes → "X GB", the hardware profile name, and the AI status label shown in the header/sidebar. |

### `src/data/demoData.ts`
Exports `welcomePrompts` (the four suggestion chips on the empty-chat screen — **used**) and `demoConversations` (a set of fake seed conversations from the original UI-only prototype — **no longer imported anywhere**, dead data left over from before real persistence existed).

## `scripts/` — packaging for a USB drive
| File | Purpose |
|---|---|
| `prepare-usb.cjs` | Takes the raw `electron-builder` output, **ad-hoc signs it** (`codesign --sign -`, since without a paid Apple Developer certificate the app is otherwise fully unsigned and crashes its helper processes on Apple Silicon), copies it with `ditto` (not a plain recursive copy — that mangles the `.app`'s internal framework symlinks and re-invalidates the signature), and assembles `usb-build/` with `runtime/` and `models/*.gguf` as sibling folders next to the app. |
| `create-dmg.cjs` | Wraps `usb-build/` into a single `.dmg` via `hdiutil`. This exists because a FAT32/exFAT USB drive cannot store the `.app` bundle's symlinks or Unix executable permissions at all — a `.dmg` (or a `.zip`) is a single regular file that any filesystem can hold, and the user drags its contents out to a real Mac filesystem before running it. |

## Two request lifecycles worth understanding end-to-end

**A normal chat message:**
`App.tsx: handleSend` → `window.portableAI.ai.generate` → `aiHandlers.cjs` → `LocalAIManager.generate()` → `buildContext()` (injects current time, attachment text, web search results if enabled, trims to fit) → `LlamaServerManager.generate()` (streams from `llama-server`'s `/v1/chat/completions`) → deltas streamed back over `portableai:ai:stream` → final message saved to SQLite.

**A Repo Assistant run:**
`AgentPanel: handleRun` → `useAgentSession.run()` → `agentHandlers.cjs`'s `portableai:agent:run` → creates a fresh `AgentSession` → loops: ask the model → execute whichever tool it calls (via `fileTools.cjs`, sandboxed by `repoAccess.cjs`) → for `write_file`, pause for `diff-pending` unless auto-apply is on → feed the tool's result back → repeat until the model gives a final answer (or the step/stall budgets run out) → every step is broadcast over `portableai:agent:event` and appended to the transcript client-side.
